# Руководство для ИИ: фронтенд маркетплейса

Эта папка содержит правила для любых ИИ-моделей, работающих с фронтендом проекта. Правила едины для всех фронтенд-микросервисов:

| Микросервис | Путь | Бэкенд |
|-------------|------|--------|
| B2C (покупатель) | `services/b2c-frontend/` | `services/b2c/` |
| B2B (продавец) | `services/b2b-frontend/` | `services/b2b/` |
| Moderation | `services/moderation-frontend/` | `services/moderation/` |

## Как пользоваться

1. **Перед любой задачей** прочитайте [`core.md`](./core.md).
2. Затем откройте файлы по теме задачи (см. таблицу ниже).
3. **Источник правды по API** — код соответствующего бэкенда в `services/{b2c,b2b,moderation}/`.
4. **Результат работы ИИ** — открытый Pull Request в отдельной ветке (не коммит в `main`). Подробности — в [`workflow.md`](./workflow.md).

## Язык

- Тексты правил и UI — **русский**.
- Термины, названия библиотек, идентификаторы в коде — **английский**.

## Критичные запреты (кратко)

- Не менять код бэкенда. При необходимости — сообщить разработчику.
- Не добавлять `data-tid` (это зона тестировщика).
- Не писать e2e, UI-автотесты, скриншотные тесты.
- Не коммитить в `main`.
- Не переписывать проект и не выходить за scope задачи.
